# Диспетчерская карта задержек Москвы

Главный экран демо: 2D-карта города сверху, транспорт, выделенная проблема и карточка выбранной машины. Рассчитан на Full HD 1920×1080; на 1440×900 и 1366×768 основные действия остаются на экране.

## Что на экране

- **Верхняя панель:** постоянная подпись режима, переключатель источника, состояние данных, кнопка «События» со счётчиком непрочитанных и раскрываемая «Диагностика» (revision, часы, время ответа, ingest/ML-счётчики, счётчики событий, происхождение геоосновы, SHA-256 раздаваемых `app.js` и `app.css` из consumer `/api/build` — по ним видно, что браузер получил новую сборку).
- **Карта** занимает всё, кроме правой панели (420 px на экранах от 1700 px, иначе 360 или 330 px). Вид всегда сверху: наклон и вращение отключены; pan, zoom и кнопка «Обзор» работают. Слева сверху — строка «Требует внимания» с самым срочным объектом и кнопкой перехода к карточке.
- **Правая панель:** в демо-режиме сверху — блок сценария (см. ниже); затем фильтры «Все / С предупреждениями / Нет данных» и «Все направления / Напр. А / Напр. Б / Без привязки» со счётчиками текущего снимка (не статистика города), поиск по отображаемому ID, «Сбросить выбор», список по срочности и карточка (закрывается «×» в заголовке): объект, прогноз задержки или его отсутствие, событие объекта (см. ниже), маршрут и направление, цель и плановое время, наблюдаемое отклонение, свежесть, состояние данных, причина («не установлена» — причины не угадываются) и действие «Показать на карте».
- **Обозначения:** машина — круг с тёмной обводкой; зелёный ≤ 2 мин, янтарный > 2 мин, красный ≥ 5 мин **только** для актуального прогноза в норме. Нет актуального прогноза (нет значения, degraded/unavailable, Backend недоступен) — полый круг. Выбранная машина — двойное кольцо, цель выбранной машины — ромб с подписью «Цель … · план …». Цвет — величина прогноза, не вероятность. В демо-режиме пунктир с кружками — **схема последовательности** точек сценария для каждого направления (синий — А, фиолетовый — Б), а не трасса по дорогам; направление выбранной машины выделено, другое приглушено. В режиме потока линий нет: строки Backend не содержат привязки к маршруту.

## Режимы источника

Режим выбирается явно переключателем или `?mode=demo` / `?mode=live`; по умолчанию — демо. Смена режима сбрасывает выбор, фильтр и поиск; возврат в демо начинает новый запуск сценария.

| Режим | Подпись | Откуда значения |
|---|---|---|
| Демо-сценарий | «Демо-сценарий · значения заданы» | [`scenario.js`](scenario.js): сценарий `moscow-center-demo` версии `d03.v1` — 8 объектов в центре Москвы, 5 фаз, «Демо-линия» с двумя направлениями; позиции, прогнозы, цели («Точка сценария …», не реальные остановки), схема и возраст заданы вручную, `prediction_source: 'scenario'` |
| Поток Backend | «Поток Backend · телеметрия NDTP» | consumer `/api/snapshot` → Backend `/v1/vehicles`; в карточке прогноз подписан «Прогноз Backend» и `model_version`, если он передан; поле «Результат модели» показывает, на каком принятом кадре NDTP (`prediction_input_frame_id`) и ревизии контекста посчитан сохранённый результат ML и хэш артефакта модели |

### Маршрут, направления и цели (D03)

Каталог в `scenario.js` (`ROUTE_CATALOG`) — единственный источник route/direction и координат целей в демо. «Демо-линия» — не официальный номер маршрута. У направлений А (А1 → А6) и Б (Б1 → Б6) свои упорядоченные точки; ключ маршрута всегда включает направление (`demo-line:a`, `demo-line:b`). Машина стоит на своём отрезке схемы, её цель — следующая точка; координата цели берётся только из каталога, отсутствующая цель остаётся «Цель не определена» и не рисуется (никогда не `[0,0]`). Д-108 без привязки: в карточке «Без привязки», в событиях он не группируется с другими.

В режиме потока строки Backend не содержат route/direction — все объекты «Без привязки». `target_stop_id` Backend — ID плановой записи расписания, а не код физической остановки; в карточке он подписан «Плановая точка …», координаты у него нет, поэтому ромб цели не рисуется.

### События и действия диспетчера (D04, D05)

Событие — эпизод задержки > 2 мин по группе `(режим источника, маршрут с направлением)`. Машины одного направления попадают в одно событие, встречное направление — отдельное, машина без привязки — своё. Состояния: «Активно» (есть текущее предупреждение), «Мониторинг потерян» (предупреждений нет, но у участника нет актуальных данных: Backend недоступен, degraded, строка пропала — это **не** завершение), «Задержка закончилась» (все участники актуальны и ≤ 2 мин). Новое предупреждение после завершения открывает новый эпизод с новым ID. Повтор того же снимка ничего не меняет: одно событие, один toast, без дублей истории.

- **Центр событий** («События» в верхней панели): активные и завершённые события, участники и их значения, пик, время открытия, статус обработки, непрочитанные отмечены. Клик по событию открывает его направление, выбирает самый срочный объект и центрирует карту.
- **Toast** справа внизу — один на новый эпизод; первое состояние после открытия страницы или сброса только учитывается в счётчике.
- **Прочитано** (открыть событие или выбрать объект), **«Взять в работу» / «Вернуть в новые»** и **«Задержка закончилась»** — разные состояния. Действие доступно в карточке объекта, пока событие не завершено.
- **Заметка** — простой текст до 280 символов; HTML не исполняется (вывод только через `textContent`), пустая заметка отклоняется. История события (открытие, добавление участника, потеря мониторинга, завершение, действия, заметки) показана в карточке со временем по часам источника.
- Всё хранится **только в этом браузере**: в демо — в пределах одного запуска сценария, в потоке — до смены режима или перезагрузки. «Сброс» и смена режима очищают события, действия и заметки.
- **Связь с водителем · прототип** (в событии, пока оно не завершено): блок с подписью «Прототип · отправка не подключена» готовит текст для водителя из текущих значений. «Скопировать текст» сообщает об успехе только после записи в буфер обмена; если буфер недоступен (например, страница открыта по http с адреса в локальной сети), текст выделяется для ручного копирования. Экран ничего не отправляет.

### Демо-сценарий: фазы и управление

| Фаза | Что видит диспетчер |
|---|---|
| 1. Обзор | Одна задержка уже есть (Д-103 на направлении А, 2.8 мин) — событие №1 уже в счётчике; Д-106 без прогноза, Д-108 без достоверного GPS и без привязки |
| 2. Прогноз обновляется | У Д-104 (направление Б) растёт отклонение, прогноз «рассчитывается» — в карточке «Нет прогноза» |
| 3. Новое предупреждение | Д-104 — 6.5 мин и Д-102 — 3.2 мин на направлении Б: одно новое событие №2 с toast; строка внимания, список и подпись на карте помечают их «Новое предупреждение». Д-103 остаётся в событии направления А |
| 4. Данные недоступны | Д-103 отключён: последний прогноз показан как устаревший и не считается предупреждением; событие №1 — «Мониторинг потерян», не завершено |
| 5. Возврат в норму | Д-103 снова на связи, Д-104 и Д-102 нагнали: все ≤ 2 мин, оба события — «Задержка закончилась» |

Главный путь M1: «Начать демо» → фаза 3 (toast) → «События» → событие направления Б → карточка Д-104 → «Взять в работу» → заметка → «Продолжить» → фаза 5 и история события.

Блок сценария в правой панели показывает фазу, её описание, состояние («ожидает запуска / идёт / пауза / завершён») и короткий ID запуска. «Начать демо» (после паузы — «Продолжить») переключает фазы раз в 8 с до последней; «Пауза» останавливает; «Далее» — одна фаза вручную. «Сброс» без перезагрузки страницы создаёт новый `scenario_run_id` (`moscow-center-demo.d03.v1.r<N>-<случайный суффикс>`) и начинает с фазы 1; выбор, фильтры, поиск, локальная история фаз, события, действия и заметки предыдущего запуска не переносятся. Полный ID и история фаз текущего запуска — в «Диагностике». Значения фаз одинаковы в каждом запуске; изменение значений требует новой `SCENARIO_VERSION`.

Ошибка Backend **никогда** не переключает в демо: показывается «Backend недоступен · последний снимок …» с устаревшими значениями либо «данных нет», если успешного снимка не было. Предупреждения по устаревшему снимку не оцениваются.

Честные состояния: «Загрузка снимка Backend…», «В снимке нет машин», «Нет машин для фильтра …», «Ничего не найдено по …». Если нет локального архива плиток, `manifest.json` или WebGL — «Карта недоступна: …»; точки на карте не рисуются, список и карточка продолжают работать.

## Устройство

- `app.js` — точка сборки: MapLibre GL JS 6.11.2 (BSD-3-Clause) с локальными PMTiles, обычные слои MapLibre для схемы направлений, custom-слой Three.js 0.180.0 — единственный рендер кругов машин и ромба цели (общая камера и WebGL context MapLibre, радиусы в экранных пикселях), DOM-подписи ID, панели, центр событий, toast и опрос consumer раз в 1,5 с.
- `incidents.js` — классификация строки: предупреждение (> 120 с, как правило alert в Backend), сильная задержка (≥ 300 с), нет данных; ключ маршрута с направлением, фильтры, счётчики, сортировка и поиск; локальное хранилище событий (эпизоды, жизненный цикл, прочтение, «в работе», заметки, история).
- `scenario.js` — версионированный демо-сценарий: каталог маршрута/точек, фазы, запуск (`scenario_run_id`, история) и переходы Start/Pause/Next; `app.js` рендерит его снимок теми же компонентами, что и снимок Backend.

Браузер читает только consumer; маршруты и прогнозы не вычисляет.

## Запуск

Сценарный показ без ML и Backend: `docker compose --profile ui-demo up --build -d ui-demo`, открыть `http://localhost:8003/?mode=demo`; рассказ и тезисы — в [local demo](../docs/runbooks/local-demo.md).

Сквозной режим из корня репозитория: `SOURCE_CLOCK=simulation docker compose --profile simulation up --build -d ml backend consumer emulator`; после healthy: `python scripts/start_ndtp_simulation.py`; открыть `http://localhost:8002` (демо) или `http://localhost:8002/?mode=live`. Демо-режиму Backend не нужен, но страницу раздаёт consumer. Команда не доказывает 15 минут новых прогнозов.

После изменения исходников: `npm ci --prefix dashboard && npm --prefix dashboard run build`, затем `docker compose build consumer` и пересоздать **только** consumer (`docker compose up -d --no-deps consumer`). Bundles находятся в `consumer/static/` и не правятся вручную; карта — `consumer/map/moscow.pmtiles`. Нельзя запускать эмуляторный reset параллельно с чужим прогоном.

## Происхождение геоосновы

Локальный PMTiles v3, MVT (слои `earth`, `water`, `landuse`, `roads`, `buildings`, `boundaries` и другие), bbox 37.25,55.50,38.00,56.00, zoom 0–13. Из Protomaps basemap `https://build.protomaps.com/20260925.pmtiles`, OSM replication time **2026-09-25T04:00:00Z**, источник OSM/ODbL (© OpenStreetMap contributors); metadata и sha256 находятся в `consumer/map/manifest.json` и видны в «Диагностике». Это **геометрия OSM**, а не маршрут автобуса. Подписей улиц нет: шрифтовые glyphs не поставляются. Воспроизводимая команда с go-pmtiles v1.31.2:

```sh
pmtiles extract https://build.protomaps.com/20260925.pmtiles consumer/map/moscow.pmtiles --bbox=37.25,55.50,38.00,56.00 --minzoom=0 --maxzoom=13
shasum -a 256 consumer/map/moscow.pmtiles
```

Все JS, CSS, worker и плитки раздаёт consumer по localhost; внешних запросов нет. Карта ограничена охватом bbox. `/map/moscow.pmtiles` поддерживает HTTP Range.

## Проверки

- `npm --prefix dashboard test` — классификация, фильтры, поиск, новое предупреждение, ключ маршрута с направлением, события (`normal → >120 → повтор снимка → ≤120` — один эпизод с завершением; одно направление — одно событие, встречное — отдельное; offline/нет данных — «мониторинг потерян»; «в работе» и заметки переживают опрос, заметка — простой текст) и демо-сценарий (версия, 4–6 фаз, 6–12 объектов, всё внутри bbox, цели только из каталога, подпись scenario, покрытие состояний, Start/Pause/Next, три одинаковых запуска с разными ID, события по фазам).
- `npm --prefix dashboard run build`, `.venv/bin/python -m pytest -q tests/test_consumer.py`.
- Browser check реальной раздаваемой сборки: поднять consumer (например `BACKEND_URL=http://127.0.0.1:8001 .venv/bin/uvicorn consumer.service:app --port 18882`), затем `UI_URL=http://127.0.0.1:18882 UI_EVIDENCE_DIR=/absolute/dir npm --prefix dashboard run check:browser`. Демо (включая направления, «Без привязки» и цель), прогон сценария (Start с автопереходом, Pause, Next по всем фазам, Reset без перезагрузки, три одинаковых запуска, остановка сценария при переходе в поток), главный путь M1 (обзор → Start → toast → «События» → направление/объект → карточка → «Взять в работу» / «Вернуть в новые» → заметка с HTML → возврат в норму и история → Reset без переноса событий), репетиция D06 (весь рассказ три раза подряд через «Сброс» с одинаковым результатом, ключевые кнопки не перекрыты, строки списка в одну строку, хэши сборки в «Диагностике» совпадают с `/api/build`), прототип связи с водителем (буфер разрешён — «скопирован» и текст в буфере; буфер недоступен — только ручное копирование, без ложного успеха) и проверки 1440×900 / 1366×768 идут без подмены; live-состояния (загрузка, Backend недоступен без снимка, online, связь результата с кадром NDTP, контекстом и артефактом модели, событие без привязки, «в работе» и заметка переживают опрос, нет прогноза и offline → «мониторинг потерян», пустой снимок, возврат ≤ 2 мин → завершение) подменяют **только** `/api/snapshot`; проверка недоступной карты подменяет **только** `/map/moscow.pmtiles` ответом 404. Для проверки «буфер недоступен» у страницы удаляется только `navigator.clipboard`. С `UI_RECORD=1` проверка дополнительно пишет резервную видеозапись рассказа `d06-backup-recording.webm` и кадры `d06-{1-overview,2-incident,3-handling}-1920.png`. Внешние запросы, page errors и console errors (кроме ожидаемых 404 в проверке карты) считаются провалом. Живой NDTP этот check не доказывает — отдельно открыть `?mode=live` без подмены.
