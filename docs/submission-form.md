# Тексты для формы «Загрузка решения»

Задача: **«Предиктор изменений в графике транспорта»**.

Ниже — четыре отдельных текста для копирования в [форму сдачи](https://reg.mt-hackathon.ru/submitsolution). Четвёртое поле объединяет сведения о производительности и дополнительные возможности. `submission.csv` загружается на платформу Data Science отдельно.

Ссылки указывают на `kroffske/transport2`, ветку `main`. Они выбраны по настроенному `origin`; публичная доступность и наличие финальной документации в `main` должны быть проверены координатором перед отправкой. Этот документ сам по себе не подтверждает публикацию, чистый clone или отправку формы.

## 1. Ссылка на рабочую систему в Docker, запускаемую по README

Скопировать в первое поле:

```text
Репозиторий: https://github.com/kroffske/transport2
Инструкция запуска: https://github.com/kroffske/transport2/blob/main/README.md#быстрый-путь-для-жюри
Docker Compose: https://github.com/kroffske/transport2/blob/main/compose.yaml

Три части системы: отдельное ML-ядро с CatBoost, Backend с приёмом NDTP и диспетчерский веб-дашборд с картой Москвы. Профиль demo поднимает пять сервисов: ML API (:8000), Backend (:8001, NDTP :9201), consumer с веб-интерфейсом (:8002), официальный эмулятор NDTP и драйвер потока.

README описывает подготовку официальных данных и загрузку образа эмулятора, проверку SHA-256 и запуск одной командой Docker Compose. Модель models/final/, локальная карта и собранный интерфейс лежат в репозитории. Три файла раздачи организаторов нужно положить отдельно: data/validate/traffic.csv, data/validate/schedule_plan.csv и data/emulator/ndtp-telemetry-emulator.tar. Их пути, размеры и контрольные суммы указаны в README.

После запуска открыть http://localhost:8002. Это локальная система; адрес localhost работает на компьютере, где запущен Docker. Веб-интерфейс показывает живой поток, прогнозы и события диспетчера; полноценный аналитический BI пока не реализован.
```

## 2. Ссылка на инструкцию для жюри

Скопировать во второе поле:

```text
Инструкция для жюри: https://github.com/kroffske/transport2/blob/main/docs/runbooks/jury-demo.md
Подробная эксплуатационная инструкция: https://github.com/kroffske/transport2/blob/main/docs/runbooks/local-demo.md
Короткий запуск: https://github.com/kroffske/transport2/blob/main/README.md#быстрый-путь-для-жюри
Описание экрана: https://github.com/kroffske/transport2/blob/main/dashboard/README.md

После подготовки трёх официальных файлов по README один раз загрузить образ:
docker load -i data/emulator/ndtp-telemetry-emulator.tar

Из корня репозитория запустить:
SOURCE_COMMIT=$(git describe --always --dirty --abbrev=40) docker compose --profile demo up -d --build --force-recreate --remove-orphans

Поток подаётся автоматически. Драйвер читает исторические GPS-точки из data/validate/traffic.csv и передаёт их официальному эмулятору через POST /api/config. Эмулятор отправляет пакеты NDTP в Backend. По умолчанию используется окно 06:30–08:30 дня 2026-01-06, 16 ТС и ускорение ×5; настройки окна и скорости приведены в инструкции. Отдельная ручная отправка пакетов для основного демо не требуется.

Открыть http://localhost:8002 (экран рассчитан на 1920×1080). В шапке видны прогон, время данных и состояние потока. Выбрать ТС на карте или в списке: в карточке виден прогноз задержки на целевой остановке через 10–15 минут; при отсутствии прогноза показана причина. Предупреждения о задержке больше 2 минут доступны в разделе «События», где можно взять событие в работу и добавить заметку.

«Диагностика» показывает принятые кадры, состояние драйвера, прореживание потока, очереди и счётчики ML, а также идентификатор сборки. Те же данные доступны через http://localhost:8002/api/snapshot и http://localhost:8002/api/build. Это эксплуатационные счётчики; локальные метрики качества модели приведены в README и документации.

Повтор команды запуска создаёт новый прогон и сбрасывает историю. Остановка: docker compose --profile demo down. В инструкции есть сценарий показа за 2–3 минуты и разбор типичных ошибок.
```

## 4. Производительность и реализованные дополнительные возможности

Скопировать в четвёртое поле:

```text
Измерения производительности: https://github.com/kroffske/transport2/blob/main/.tasks/_archive/T-4-2026-09-25-backend-dashboard-infra/qa.md
Сводка и ограничения: https://github.com/kroffske/transport2/blob/main/docs/runbooks/local-demo.md

Подтверждённые замеры относятся к исторической интеграции T-4: три сервиса, historical NDTP replay 11 ТС, ускорение ×30. Независимая проверка выполнена на commit a0a38102d52a09edef04c22060c78f792963a9c2, включающем исправления 036f589. Стенд: Apple M5 Pro, Docker VM 18 vCPU и около 7,75 ГиБ RAM. Это не benchmark нынешнего пятисервисного демо с официальным эмулятором.

- От отправки кадра до подтверждения приёма Backend: P50 1,778 мс, P95 2,947 мс, P99 8,975 мс; 1630 измерений.
- От отправки кадра до первого наблюдения соответствующего нового прогноза в consumer API: P50 142,715 мс, P95 569,975 мс, P99 1118,503 мс; 156 измерений. Эта задержка включает опрос API, а не отрисовку браузера.
- За 49,912 с отправлено 1630 кадров: 1611 новых записей и 19 повторов; 161 успешный запрос к ML, 10 промежуточных заданий объединены, ошибок протокола и переполнения очередей нет.
- Старт трёх сервисов из уже собранных образов до healthy: 16,982 с. Скачивание и первая сборка зависимостей в это время не входят.
- При остановке ML приём кадров и snapshot продолжали работать; последний успешный прогноз сохранялся с возрастом и признаком неактуальности. После запуска ML первый новый прогноз наблюдался не позже чем через 1,036 с.
- При искусственном лимите очереди 1 из 26 000 кадров 74 приняты, 25 926 явно отклонены из-за заполненной очереди; очередь оставалась ограниченной и затем разгрузилась.

Реализованные дополнительные возможности:
- Официальный эмулятор NDTP в Docker без изменения образа организаторов; драйвер подаёт ему исторические GPS-точки. Настраиваются окно данных, ускорение ×1–100 и период подачи; диагностика показывает долю прореженных и повторённых точек.
- Локальная карта Москвы и локально собранный интерфейс: при показе карты не требуются внешние запросы. Маршруты приближённо восстановлены по GPS, привязаны к остановкам и показывают раздельные встречные направления; это не официальные трассы и не map matching, а участки без достаточных данных остаются прямыми.
- Признак отклонения от маршрута с порогом 400 м и снятием ниже 250 м, направление движения ТС. В карточке отдельно подписаны факт, прогноз модели и допущение о сдвиге после цели.
- Центр событий с предупреждениями о прогнозе задержки больше 2 минут, отметками прочтения, взятием в работу, заметками и историей. Действия хранятся в текущем браузере и очищаются при новом прогоне.
- Идентификатор прогона run_id, его состояния и прогресс; повтор команды запуска начинает новый прогон, открытая страница очищает прежние события и историю автоматически.
- Версия модели и SHA-256 артефакта в прогнозах, связь прогноза с входным кадром и контекстом. API /api/build показывает source_commit и контрольные суммы интерфейса. Модель и карта снабжены SHA-256 для проверки воспроизводимости.
- Ограниченные очереди с явными отказами при переполнении, обработка повторных кадров и переподключения NDTP, сохранение последнего успешного состояния при сбоях ML. Причины отсутствия или неактуальности прогноза показаны пользователю.
- При смене целевой остановки предыдущий прогноз временно удерживается только вместе с предыдущей целью и пометкой «обновляется»; новая цель считается первой в очереди, а удержание ограничено тремя минутами времени данных.

Модель CatBoost имеет локальную среднюю абсолютную ошибку (MAE) 44,01 с на validate и 45,00 с на test; это офлайн-оценка, а не измеренная точность текущего потока. Ограничения: модель обучена на одном дне (2026-01-06), выдаёт точечный прогноз без вероятности и объяснения причины задержки; время предупреждения до начала задержки не измерялось. Полный BI и серверное хранение действий диспетчера пока не реализованы.
```

## Проверки перед отправкой

- Открыть репозиторий и все четыре группы ссылок без авторизации; подтвердить, что в `main` находится сдаваемый код и документация.
- Проверить запуск из чистого clone с официальными файлами по README. Сверить `source_commit` в `/api/build` с проверяемой сборкой; суффикс `-dirty` означает незакоммиченные изменения.
- Если появится завершённый benchmark текущего пятисервисного демо, заменить исторический блок на его измерения с идентификатором сборки и источником. Иллюстративные числа из плана T-10 не являются результатами.
- Не вставлять в поля обещание внешнего deploy: адреса `localhost` относятся к системе, запущенной жюри по README.
