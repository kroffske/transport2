## 4. Производительность и дополнительные возможности

```text
В замере предыдущей версии на историческом NDTP-потоке медианное время от отправки кадра до появления нового прогноза в API — 143 мс; 95% измерений — до 570 мс. Стенд: Apple M5 Pro, Docker VM с 18 vCPU и 7,75 ГиБ RAM, 11 ТС, ускорение ×30. Это замер API, без отрисовки браузера; текущий режим с официальным эмулятором отдельно не измерен.
Подробности: https://github.com/kroffske/transport2/blob/main/docs/runbooks/local-demo.md#историческое-t-4t-6-до-единого-демо

Дополнительно: локальная карта Москвы, маршруты и остановки, предупреждения о прогнозе задержки больше двух минут, заметки диспетчера и диагностика потока. При сбое ML сохраняется последний прогноз с отметкой неактуальности. Маршруты восстановлены приближённо по GPS; заметки хранятся в браузере. Полный аналитический BI не реализован.
```

Ссылки ведут в `main`: перед отправкой эта ветка должна содержать актуальные файлы и быть доступна жюри.
