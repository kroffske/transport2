# Scorecard критериев транспортного предиктора

Операционная проекция [официальных критериев](transport-delay-predictor.md). Она нужна для приоритизации и оценки готовности. Официальные баллы присваивает жюри; колонка «Подтверждено сейчас» означает только наличие проверяемого локального доказательства. «Выполнимость» — предварительная оценка возможности выполнить работу, а не вероятность получить максимальный балл.

## Правила обновления

1. Балл не повышается по наличию файла, кода или архитектурной схемы без требуемого поведения.
2. C1 обновляется только по валидному platform score; локальный MAE остаётся диагностикой.
3. C2 не закрывается офлайн-предсказаниями или одним плановым окном T+10…15: требуется наблюдаемое начало инцидента и фактическое упреждение алерта. При отсутствии достаточной onset-разметки ограничение остаётся открытым.
4. C3 требует рабочей цепочки всех трёх модулей, а не отдельных контейнеров.
5. C4 требует наблюдаемого интерфейса и live data, а не mockup.
6. C5 требует метрик и failure-path evidence.
7. Каждое изменение scorecard ссылается на task evidence или внешний readback.

## Приоритет

Сначала получить C1 evidence и основу C2 через честную модельную задачу. Затем собрать C3–C5 одним системным контуром. Pitch планируется после появления воспроизводимого demo-path.
