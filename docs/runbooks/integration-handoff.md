# Передача текущей модели и интеграции

## Текущее состояние (2026-09-27)

Интеграция реализована одним демо: официальный эмулятор NDTP (драйвер `scripts/emulator_driver.py` подаёт ему GPS из `data/validate/traffic.csv`) → Backend (прогон и часы в `transport_backend/run.py`, `cur_dev_s` по прошлым GPS и плану) → отдельный ML API с выбранным artifact → consumer → диспетчерская карта с маршрутным контекстом и прогнозом на цели. Запуск одной командой и ограничения — в [local demo](local-demo.md), экран — в [`dashboard/README.md`](../../dashboard/README.md), контракт — в [Backend v1](../api/backend-v1.md). Разделы «Реальный разрыв интеграции» и «Граница интерфейса» ниже — историческая запись до этой работы; актуальными из них остаются только ограничения модели.

Что по-прежнему отсутствует: `route_id`, реальные трассы маршрутов и устойчивые stop ID (на карте — путь по GPS прогона, а не трасса), воспроизведение реальных задержек доставки NDTP (время пакета ставит эмулятор), серверное хранение действий диспетчера (они живут только в браузере и сбрасываются с новым прогоном), канал связи с водителем (только прототип текста), измерение lead-time до начала инцидента (onset evidence), полный BI/C4 и официальный score.

## Реальный разрыв интеграции

Историческая запись до T-4: первый абзац закрыт интеграцией (см. «Текущее состояние»); ограничения модели в двух следующих абзацах остаются в силе.

`transport_ml/service.py`, Predictor и compose.yaml пока ориентированы на старые `artifacts/context` и `artifacts/core`. Актуальный .cbm не является drop-in replacement: новые признаки, metadata и отсутствие заново проверенных risk/quantile моделей требуют явного адаптера и контракта. Первый полезный срез должен перенести reusable inference из локального опыта в owning ML package, сопоставить offline/API predictions и явно загрузить выбранную модель.

Модель обучена на одном сервисном дне и известных машинах. Признаки используют нормализованное время относительно 2026-01-06. При проектировании replay/serving проверить часы, идентичность машины, построение `cur_dev_s`, target stop и применимость на другом дне. Не заявлять перенос на новые дни без проверки.

ML умеет точечную задержку. Вероятность риска, объяснения причины и интервал нельзя объявлять откалиброванными свойствами этого нового артефакта. Плановое окно 10–15 минут не доказывает lead-time до начала инцидента; C2 требует отдельного измерения.

## Исходники и локальные файлы

`.local`, `artifacts`, task artifacts, сырые train/test/validate/labels и tar эмулятора не коммитятся. Они доступны в основном checkout, но не появятся автоматически в новом worktree. Перед запуском worker обеспечить ему точные read-only пути или поддерживаемое подключение нужного локального артефакта. Не копировать датасет и все эксперименты в Git.

Исходники transport_ml, контракты tests и исторические notebooks T-3 входят в checkpoint. Они не заменяют актуальный локальный model card. Старые эксперименты до очистки синтетики сохраняются для происхождения.
