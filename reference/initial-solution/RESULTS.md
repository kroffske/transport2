## Критическое ограничение алертов

Порог 0.481875 выбран по calibration с целью precision>=0.8.
На audit фактически precision=0.75 и recall≈0.462: цель на настройке не гарантирует результат.
Все 16 алертов audit пришлись на точки с cur_dev_s>120.
На подгруппе cur_dev_s<=120 было 11 будущих late, но ни одного алерта: **0/11 recall**.
Это point-level прокси новых задержек, а не полноценный event-level recall.
Таким образом, базовый регрессор полезен, но ранние предупреждения новых сбоев еще не готовы.

Отдельная модель/политика для onset, разметка эпизодов, calibration этой подгруппы
и новый контрольный период — следующий обязательный этап. Нельзя просто понизить
порог по уже просмотренному audit и объявить новый результат независимым.

## Проверки

14 pytest-тестов прошли. Проверены: изменение будущей телеметрии, поздние исправления,
недоступность факта и target в признаках, горизонт, пустой контекст, аномальная скорость,
зрелость меток в split, дубли ID, порядок и знак submission, запрет NaN и недостающих ID.
Через FastAPI TestClient проверены normal inference, degraded fallback,
совпадение online/offline prediction и HTTP 422 для неправильного горизонта.

Python 3.13.5 / CatBoost 1.2.8 / PyTorch 2.10.0+cpu.
Docker build и GPU не проверялись. Настоящий NDTP-поток не запускался.
Submission не создан: validate-входов нет. Новые независимые дни не проверялись.
