Use the accepted task outcome and current roadmap as the execution contract.

For a feature, state the user-visible outcome and non-goals, identify the existing owner and caller,
choose the smallest complete behavior, and implement all planned items before whole-change review.
For a bug or fix, reproduce the failure, isolate its owning layer, repair the confirmed cause, and
add regression proof. For documentation, start from code, configuration, tests, or another named
source of truth and update only affected documents. For research or audit work, name the decision
or boundary, collect evidence before conclusions, and route implementation changes back through
planning.

Run task Verification and required independent acceptance before closure. Use locus-ship only for
the delivery boundary authorized by the user and repository. Before handoff or stopping, record
concrete work, constraints, checks, and the next owner with task update --note. On resume, reconcile
the latest note with current files and evidence; a note or prior workflow result is not proof that a
check still passes.
