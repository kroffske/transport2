# T-5: Оптимизировать ML для score выше 0.70

## Outcome

Primary goal: Улучшить воспроизводимый ML-прогноз для достижения platform score > 0.70, подготовить проверенный submission и честно указать достижимость порога по доступной оценке.
Direction: on-track

## Decisions

- **Актуализация по запросам пользователя 2026-09-26:** пользователь разрешил восстановить validate-ответы для оценки и выбирать по ним модель/параметры, сохраняя их вне fit. Это заменяет нижеописанный первоначальный запрет реконструкции и rolling-only отбор. Финальное локальное evidence: `.local/validate-tuning-2026-09-26/report.md`; durable handoff: `docs/runbooks/integration-handoff.md`. Старые runs не переписываются.
- Текущая модель обучена на 4139 строках после исключения 88 синтетических производных validate и 207 производных test. MAE validate 44.01 с / test 45.00 с; 0.821/0.795 — только условные score при MAE_TARGET=30. Официальный score пока неизвестен. Актуальная модель ещё не подключена к старому FastAPI/Compose.

Первоначальная политика и бюджет сохранены ниже как контекст первых runs:

- T-3 сохраняется без изменения. Новая экспериментальная политика v1 использует три expanding временных fold (10:00–14:00, 14:00–17:30, 17:30–20:30), purge созревания метки + 15 минут. Основная метрика — pooled MAE на реальных машинах; дополнительно все строки и каждый fold. Synthetic tr_id >= 9000000 имеет исследуемый вес 1 или 0.25.
- Audit T >= 20:30 и labels_test открываются только после выбора в текущем run; они ранее экспонированы и остаются диагностикой. Validate target не реконструируется. Признаки допускают только event_time и receive_time <= T, план без факта и cur_dev_s.
- Гипотеза: signed отставание GPS по плановым сегментам и снижение веса синтетики улучшат перенос на реальные машины. Бюджет — максимум 24 конфигурации CatBoost на CPU, три fold, 800 деревьев, затем одна оценка выбранного кандидата и refit. Stop: завершение бюджета, техническая ошибка либо отсутствие улучшения.
- Сравнение с T-3 recipe на тех же fold; сохранённый T-3 остаётся shipping reference. Выбор по CV фиксируется до диагностики. Независимость исторических данных не заявляется.
- `MAE_TARGET` отсутствует в исходном README. Точный score неизвестен; для 0.70 нужна MAE <= 0.30 * mae_zero + 0.70 * MAE_TARGET. У пользователя запрошено значение/ссылка. C1 не повышается без platform readback.
- Общие признаки принадлежат FeatureBuilder; новая версия включается metadata модели и доступна batch/API. optimize CLI владеет воспроизводимым сравнением, сохранением конфигураций, OOF и моделей. Старый train и артефакты сохраняют legacy профиль.

## Verification

- Признаки неизменны при добавлении будущей телеметрии, поздней коррекции, фактических времён и labels.
- Fold исключают несозревшие labels; реальные/synthetic ошибки показаны раздельно. Отбор воспроизводим по сохранённым OOF.
- Сохранённая модель даёт тот же submission при свежем inference; схема, порядок, конечность и 151 ID проверяются readback.
- Existing tests + focused tests, compileall. Никакой официальный score не выдаётся за измеренный без платформы.
