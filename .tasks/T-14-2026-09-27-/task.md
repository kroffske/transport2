# T-14: Настройки оператора: выбор своих маршрутов в демо

## Outcome

Primary goal: диспетчер в демо выбирает в настройках «Мои маршруты» (галочки по маршрутам, по умолчанию — все) и видит на карте, в списке «Транспорт», в очереди «События», строке «Требует внимания» и toast только ТС своих маршрутов. Выбор задаётся форматом настроек оператора `transport.dispatcher-settings.v1`, который позже можно выдавать оператору извне.
Direction: on-track
Comment: User 2026-09-27: «какому-то оператору выдавались определённые маршруты… именно маршруты, не автобусы». В данных `route_id` нет (docs/api/backend-v1.md: «`route_id` в данных нет»), есть только `tr_id` наряда.

### Result examples

```json
{"format": "transport.dispatcher-settings.v1", "operator": "Диспетчер", "routes": ["R-3f2a1c", "R-9b07e4"]}
{"format": "transport.dispatcher-settings.v1", "operator": "Диспетчер", "routes": "all"}
```

Панель настроек: `☑ R-3f2a1c · Каширское ш. — Борисовский пр. · ТС 122048` … «Все» / «Снять все», счётчик «Мои маршруты 2 из 13».

## Decisions

- Идентификатор маршрута выводится Backend из плана: `route_key = "R-" + sha1(отсортированное множество geom плановых остановок наряда)[:6]`. Наряды с одинаковым набором остановок — один маршрут (в train 26 синтетических нарядов 9000000+ совпадают с реальными 1:1 по набору остановок). В демо-плане validate 13 нарядов → 13 разных маршрутов, т.е. сейчас маршрут и ТС совпадают 1:1 — это свойство данных, а не UI.
- `route_label` — адреса двух самых удалённых друг от друга остановок (конечные), улица без номера дома; без адреса — ближайший адрес в 300 м, иначе «—».
- ТС без наряда в плане: `route_key=null`, в настройках — отдельный пункт «Без наряда».
- Очередь событий по-прежнему наблюдает все ТС (иначе скрытый маршрут переводил бы события в «Мониторинг потерян»); фильтр — только на показе. Смена набора снимает выбор скрытых событий.
- Хранение настроек — `localStorage` браузера (переживает перезагрузку и смену прогона); серверной выдачи операторам нет — это следующий шаг.
