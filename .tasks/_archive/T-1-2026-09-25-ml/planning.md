# Планирование T-1

## Q0: Goal alignment

Direction: on-track

Пользователь явно принял Prompt Draft и поручил создать репозиторий. Это является owner intake для локальной структуры текущего этапа. Внешняя публикация и последующая архитектурная переработка не приняты.

## Наблюдения

- Целевой каталог изначально пуст и не является Git-репозиторием.
- Официальная раздача занимает около 212 МБ; `ndtp-telemetry-emulator.tar` занимает 134 284 800 байт.
- Начальное решение занимает около 2,4 МБ и уже содержит Python-пакет, тесты, Docker/Compose, модели, результаты и сгенерированную документацию.
- `transport_ml_solution/docs/dataset_README.md` побайтно совпадает с `dataset/README.md`.
- Обе копии `Emulator-and-Telematic-Packets-Specification.md` побайтно совпадают.
- Dockerfile и Compose используют корневые пути `transport_ml/`, `requirements*.txt` и `artifacts/`; их сохранение снижает объём последующих исправлений.

## Pressure pass

- Хранение 134-МБ tar в Git создаёт прямой риск невозможности обычного push. Решение: копировать локально, игнорировать Git.
- Перенос Python-пакета под `src/` сейчас ломает Dockerfile и команды запуска. Решение: сохранить текущий путь, реорганизацию выполнять отдельной задачей вместе с импортами и упаковкой.
- Дублирование официальных документов создаёт неясного владельца. Решение: использовать копию из `dataset`, а в карте источников зафиксировать исключённые идентичные дубли.
- Пустой `dashboard/` может выглядеть как реализованный модуль. Решение: README должен явно называть его будущей поверхностью.
- Артефакты обучены на малой выборке, но относятся к начальному решению, а не к официальным данным. Решение: сохранить с явной маркировкой происхождения; не выдавать их за результаты на полном датасете.

## Handoff

Первый исполнимый срез: скопировать начальное решение с сохранением его рабочих относительных путей, затем добавить официальную раздачу под `data/`, официальный PDF и навигационную документацию. Принимать по контрольным суммам и Git-boundary, без запуска приложения.

## Уточнение после docs gate

Оригинальные Markdown-документы начального решения перенесены из планировавшегося `docs/source/initial-solution/` в `reference/initial-solution/`. Причина: authored pages под `docs/` обязаны иметь Locus-frontmatter, а задача требует сохранить эти исходники побайтно. PDF остаётся в `docs/source/official/`; изменение не затрагивает пользовательскую границу или содержимое источников.
