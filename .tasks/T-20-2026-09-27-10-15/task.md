# T-20: Демо: явный горизонт прогноза 10–15 мин и полное окно телеметрии

## Outcome

Primary goal: после слияния UX-правок (T-19) на экране явно видно и проверкой доказано, что система даёт прогноз на 10–15 минут вперёд, как требует задача: диспетчер читает «к ост. N по расписанию 08:42 ожидается 08:45 (+3 мин)» и понимает, что это горизонт 10–15 мин от времени данных. Демо проигрывает полную телеметрию (не только окно 06:30–08:30), допускает ускорение ×10, а окно и скорость задаются при перезапуске без ожидания полного прогона; в репозитории закоммичено понятное окно по умолчанию без привязки к дате.
Direction: on-track
Comment: Пользователь 2026-09-27 ~21:45 МСК (голосом): «ясно показать про задержку», «расширить предсказательное время / demo window, чтобы проигрывалось по полной телеметрии», «можно ×10, на демо ×5», «при перезапуске поиграться интервалами», «закоммитить понятное время без привязки к дате», «проверить, что не только с шести всё работает». Делать ПОСЛЕ завершающего merge T-19 и только если пункты ещё актуальны.

## Decisions

- Старт — после merge T-19 в main. Сначала оценить, что уже закрыто: T-16 выводит «Цель прогноза · ост. N / По расписанию / Ожидается / Опоздание по прогнозу» и подсказку ⓘ про горизонт 10–15 мин. Если горизонт виден только в подсказке — вынести его в видимую строку (например «Прогноз на 10–15 мин вперёд: к ост. 12 в 08:42 ожидается 08:45 · +3 мин») или в метку цели на карте; выбрать один вариант и обосновать.
- Требование «10–15 мин» доказывается проверкой, а не только текстом: тест/browser-check утверждает, что для каждого ТС с прогнозом `target_time_begin − время данных` ∈ (10, 15] мин (правило `transport_backend/schedule.py:169-172`), и что ожидаемое = план + прогноз.
- Окно демо: сейчас `compose.yaml` → `DEMO_WINDOW=${DEMO_WINDOW:-06:30-08:30}`, `DEMO_SPEEDUP=${DEMO_SPEEDUP:-5}` (формат уже время суток без даты). Выяснить фактический диапазон телеметрии и расписания в данных; дефолт — полный диапазон или понятное широкое окно; ×5 для показа, ×10 допустим, если драйвер/ML/очереди держат нагрузку (проверить drops/queue из `/api/snapshot.processing`).
- «Не только с шести»: прогнать хотя бы одно окно, начинающееся не в 06:xx (например дневное и вечернее), и убедиться, что цели, прогнозы и события появляются.
- Общий docker-стек перезапускать только согласовав с соседними сессиями transport2.

## Boundary

- **Included:** видимое объяснение горизонта прогноза; проверка требования 10–15 мин; окно/скорость демо (compose, runbook, README); прогоны в разных окнах.
- **Excluded:** изменение модели и правила выбора цели; новые UX-разделы сверх этого.
